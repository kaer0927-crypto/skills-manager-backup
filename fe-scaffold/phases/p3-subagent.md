# P3 并行分析 + 子任务 Prompt 生成

> **角色**：并行编排调度器。分析依赖 → 分组分轮 → 为每个子 Agent 写自包含 Prompt。
> **产出**：`subagent_prompts.md`

## 前置输入

- `implementation_plan.md` + `task.md`（均已确认）
- `references/quality-redlines.md`（生成 Prompt 时要用其第五节的内嵌摘要）

## 三原则

1. **文件互斥**：各子 Agent 操作的文件列表零重叠——绝对不可两个子 Agent 改同一个文件
2. **依赖单向**：后执行者只依赖先执行者的产出，不得互相依赖；发现环形依赖 → 告知用户并给出合并方案
3. **Prompt 自包含**：单独拿到一个 Prompt 就能完整执行，不需要本对话的任何上下文，**也不引用本机文件路径之外的任何资源**

## 执行步骤

### Step 3.1 — 文件依赖分析

从 task.md 提取全部变更文件，分析四类依赖：import 依赖、store 读写、类型引用、mock 数据引用。输出文件依赖图（文字版即可）。

### Step 3.2 — 轮次规划

| 判断条件 | 决策 |
|---------|------|
| 文件被 >2 个任务依赖 | Round 1（基础层：store/types/config/layout/router） |
| 文件间无 import 关系 | 同 Round 并行 |
| 文件间有 import 关系 | 跨 Round 串行（先被依赖后使用） |

并行度：1–4 文件 → 1 个 Agent；5–10 → 2–3 个；11+ → 3–5 个。

```
Round 1:  Agent A（基础层）        ← 必须先跑完
Round 2:  Agent B / C / D          ← 并行
Round 3:  验收修复（P5）
```

### Step 3.3 — 生成每个子 Agent 的 Prompt（7 模块缺一不可）

1. **角色与项目环境**：`你是 AI 前端工程师，正在对「[项目名]」做[操作类型]。技术栈：[列表]。项目路径：[绝对路径，派发时填写]`
2. **文件职责边界**：`你只负责以下文件（只改这些，不要动任何其他文件）：` + 逐个列出（新建/修改/重写）
3. **依赖接口定义**：所需 store 接口的完整 TypeScript 签名（已由前轮 Agent 创建）+ mock 数据的 import 路径和结构说明
4. **全局风格与质量红线**：风格要求（主色/风格/全中文/作者署名）+ **完整复制 `references/quality-redlines.md` 第五节的「内嵌摘要」代码块**（⚠️ 直接嵌文本，禁止用文件路径引用——子 Agent 在别的窗口/机器上读不到）
5. **逐任务详细指令**：每个任务 = 动作 + 文件 + 交互描述（UI 结构 / 数据来源 / 用户操作→系统响应 / 禁用与边界条件）。UI 任务附布局结构和组件清单与状态映射；Store 任务附完整 interface + 初始值 + action 逻辑；Mock 任务附 ≥3–5 条完整样例数据
6. **文案替换清单**（如适用）：原文 → 改为
7. **完成检查**：`跑 npx tsc --noEmit，确保你负责的文件零类型错误（其他 Agent 未完成的文件报错可忽略）`

### Step 3.4 — 预生成 QA Prompt（P5 备用）

按 p5-qa.md 的验收流程生成一份 QA 子 Agent Prompt：编译验证循环修复 → 浏览器逐项验证（从 implementation_plan 提取清单）→ 按 P0–P3 分级修复（范围限 src/，禁改 package.json 与构建配置）→ 更新 Memory.md。

## 交付物：`subagent_prompts.md`

结构：执行策略（轮次图 + 分组理由）→ 每个子 Agent 的职责说明 + 完整 Prompt（用 `---` 包裹便于复制）→ 执行顺序总结。

## 阻断规则

- task.md 未确认 → 不生成
- 任何两个子 Agent 出现文件交集 → 重新分组
- 🔴 GATE：产出后暂停。告知用户下一步进入 P4 执行（读 `phases/p4-execute.md`，按环境选择自动派发或手动多窗口）
