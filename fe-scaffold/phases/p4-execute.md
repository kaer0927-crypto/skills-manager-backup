# P4 并行执行（能力自适应）

> **产出**：各子 Agent 写入项目的代码文件
> 先判断环境：有原生子 Agent/并行任务能力 → 模式 A；没有（或用户想手动控制）→ 模式 B。

## 模式 A：自动派发（环境支持子 Agent 时）

主对话直接编排执行：

1. **Round 1**：派发基础层 Agent（Prompt = subagent_prompts.md 中 Agent A 的完整内容），等待完成
2. **轮间校验**：确认基础层文件已生成（store/types/config/layout/router 存在，`npx tsc --noEmit` 基础层无错）；未通过 → 先修复再进下一轮，**不得抢跑**
3. **Round 2**：并行派发本轮全部 Agent（一次性发出，让它们并发执行）
4. 全部完成 → 汇总各 Agent 回报（完成的文件清单、遗留问题）→ 进入 P5
5. 某个子 Agent 失败 → 按下方「异常处理」定位，修复后**只重跑该 Agent**

派发时的注意：每个子任务用 subagent_prompts.md 里的 Prompt **原文**（已自包含），补充项目绝对路径；不要额外附加对话上下文。

## 模式 B：手动多窗口（无子 Agent 能力时的操作手册）

指导用户操作：

1. **Round 1**：新开一个对话窗口（任意 AI 编码工具均可），把 Agent A 的 Prompt（`---` 之间内容）完整粘贴进去，等执行完成
2. **验证基础层**：确认新文件已创建；可选在终端跑 `npx tsc --noEmit`
3. **Round 2**：为每个 Agent 各开一个独立窗口，同时粘贴各自 Prompt，并行执行
4. 主对话中维护执行状态表：

| 子Agent | 职责 | 状态 | 备注 |
|---------|------|------|------|
| A | 基础层 | ✅ 已完成 | |
| B | [职责] | 🔄 执行中 | |
| D | [职责] | ⏳ 待执行 | 等 B 完成 |

5. 全部完成后回到主对话说「全部完成」→ 进 P5

> ⛔ 模式 B 下主 Agent 在 P3→P5 之间的唯一职责是答疑（参考 implementation_plan.md 回答），**严禁自己动手写代码**——那会跟子窗口产生文件冲突。

## 异常处理（两种模式通用）

| 现象 | 原因 | 解决 |
|------|------|------|
| import 报错 | 基础层文件路径有误 | 检查实际文件位置 |
| 类型报错 | types 定义与使用不一致 | 回基础层 Agent 修 types |
| store 方法不存在 | Prompt 中定义的 action 未实现 | 回基础层 Agent 补实现 |
| 样式冲突 | 两个 Agent 都写了全局 CSS | 检查文件分工是否重叠 |

## 铁律

1. 两个子 Agent 不得操作同一文件
2. Round 1 完成并校验通过之前，不得启动 Round 2
3. 每个 Prompt 自包含，无需附加上下文
4. 全部子任务完成后才能进 P5 验收
