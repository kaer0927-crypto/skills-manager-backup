# P5 验收与修复（不可跳过）

> **角色**：质检工程师。验证全部产出，修复问题，确保交付质量。可由主 Agent 执行，也可把 P3 预生成的 QA Prompt 派给子 Agent 执行。
> **产出**：验收报告 + `Memory.md` 更新

## 前置输入

- 全部子任务已完成
- `implementation_plan.md`（验证标准）+ `task.md`（任务清单）

## 执行步骤

### Step 5.1 — 编译验证

```bash
npx tsc --noEmit 2>&1 | head -100
```

（Shell 不可用 → 输出命令请用户执行回贴。）有错误时按类型修复：import 路径 / 类型缺失 / store API 不匹配 / 未使用导入 / 旧文件引用新接口。修复原则：**只修报错，不做功能重构**。循环执行直到 0 错误。

### Step 5.2 — 运行验证

```bash
npm run dev
```

确认：正常启动、无编译错误、控制台无红色报错，记录端口。

### Step 5.3 — 浏览器功能验证

从 implementation_plan 的 Verification Plan 提取清单，逐项验证：

- **有浏览器自动化工具** → 自动逐项操作验证，截图留证
- **没有** → 输出结构化人工验证清单（每项：操作步骤 → 预期结果 → ✅/❌ 待勾选），请用户在浏览器逐项确认并回报结果

### Step 5.4 — 问题修复

| 级别 | 标准 | 处理 |
|------|------|------|
| P0 致命 | 白屏 / 崩溃 / 路由不通 | 必须修复 |
| P1 严重 | 菜单无响应 / 状态不联动 / 文案未替换 | 必须修复 |
| P2 一般 | 样式错位 / 数据展示不完整 | 尽量修复 |
| P3 轻微 | 细微 hover / 图表精美度 | 记录不修 |

修复范围：✅ `src/` 下任意文件；❌ `package.json`、`vite.config.ts`、`tsconfig*.json`；需要新依赖才能修 → 记录问题，交用户决策。

### Step 5.5 — 更新 Memory.md（先于验收报告）

```markdown
### [YYYY-MM-DD] fe-scaffold/[版本号] [里程碑名]
- **产出**：核心变更列表 + 新增/废弃文件
- **关键决策**：[本次的技术决策]
- **验证**：tsc ✅/❌ | dev ✅/❌ | 浏览器 N/N ✅/❌（未通过项说明）
```

### Step 5.6 — 验收报告

编译结果（问题数/已修复数）→ 浏览器验证逐项 ✅/❌ → 修复记录（级别 + 方式）→ 遗留问题（P3 级 + 建议）。

## 阻断规则

- P0 问题未修复 / `tsc --noEmit` 有错误 → 不得标记验收通过
- Memory.md 更新必须在验收报告之前完成
