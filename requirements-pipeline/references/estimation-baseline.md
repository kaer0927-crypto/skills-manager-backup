# 工作量估算基准（B端 / 政务系统）

> P3（估算）与 P6（预算审查）共用此基准。数字为行业经验区间，团队有实测数据时**永远优先用实测数据**，并把偏差回写到本文件（持续校准）。
> 基准假设：3–8 人小团队、成熟技术栈、Java/前后端分离类企业级开发。

## 一、子功能三档基准（单位：人天）

| 档位 | 判断特征 | 后端 | 前端 | 合计 |
|------|---------|:---:|:---:|:---:|
| **简单** | 单表 CRUD：列表（搜索/筛选/分页）+ 表单 + 详情，无复杂校验 | 1.5–2 | 1.5–2 | 3–4 |
| **中等** | 多表关联 / 状态流转 / 较多业务校验 / 批量操作 / 导入导出 | 3–5 | 2–4 | 5–9 |
| **复杂** | 工作流对接 / 算法逻辑 / 多系统对接 / 复杂报表 / 大数据量优化 | 5–10 | 3–6 | 8–16 |

估算方法：把 P2 清单中每个子功能归档位 → 模块小计 → 全项目合计。**归档时偏保守（往上取），Demo 心态估算是超支的第一原因。**

| 公共能力 | 方案 | 人天 |

| 阶段 | 占比 | 说明 |

## 四、复杂度修正系数（可叠乘，谨慎使用）

## 五、人力单价参考区间（元/人天，二三线城市外包/交付团队口径）

初级开发 600–900 · 中级开发 900–1400 · 高级开发/组长 1400–2000 · 项目经理 1200–1800 · UI 设计 800–1200。
一线城市/甲方现场约 ×1.3–1.5。**报价时优先用公司实际口径，此表仅兜底。**

## 六、健康度速查公式（P6 审查同款）

```
可用人天       = 团队人数 × 工期周数 × 5 × 0.8（有效工作系数）
单功能点均摊人天 = 可用人天 ÷ 功能点总数

< 1 人天/点   → ⚠️ scope 过大，必须裁剪或加资源
1–2 人天/点  → 正常区间
> 3 人天/点  → scope 偏小，可上浮功能或压缩报价
```
