# 需求分析流水线（P0–P6）

> 作者：liuyz | 版本：V3.0（可移植版）| 适用：B 端 / 政务 / 企业内部系统类项目

把一个模糊的客户需求，加工成可发客户确认、可支撑报价排期的专业交付物。共 7 个阶段，每个阶段的详细执行规程在本技能目录的 `phases/` 下，**执行某阶段前必须先读取对应阶段文件**。

## 流水线全景

```
P0 售前行业与竞品深度调研（可选）→ study/[对象]_横纵分析报告.md
P1 需求采集与结构化              → Memory.md（项目概览）
P2 功能模块拆解 V1               → study/01_功能模块拆解.md（+docx）
P3 技术可行性评估                → study/02_可行性评估报告.md（+docx）
P4 参考平台对标分析（可选）       → Delta 功能清单（Memory.md）
P5 功能清单迭代                  → study/03_功能清单_VN.md（+xlsx）
P6 自审与质控（不可跳过）         → study/04_功能清单审查意见.md
```

每个阶段完成后 🔴 GATE：展示产出摘要，等用户确认后才进入下一阶段。

## 阶段路由

用户不需要记命令。按下表识别意图，读取对应阶段文件后执行：

| 用户意图（示例说法） | 阶段 | 规程文件 |
|---------------------|:---:|---------|
| 行业调研 / 竞品研究 / 先摸底这个行业 | P0 | `phases/p0-research.md` |
| 客户提了需求 / 整理一下需求 / 需求采集 | P1 | `phases/p1-collect.md` |
| 拆功能 / 出功能清单 / 功能模块拆解 | P2 | `phases/p2-breakdown.md` |
| 可行性 / 工作量 / 排期 / 报价 / 技术选型 | P3 | `phases/p3-feasibility.md` |
| 对标XX平台 / 参考竞品补功能 | P4 | `phases/p4-benchmark.md` |
| 合并需求出新版清单 / 功能清单迭代 | P5 | `phases/p5-iterate.md` |
| 审一下清单 / 质量检查 / 发客户前把把关 | P6 | `phases/p6-review.md` |
| 走一遍完整需求分析 | P1→P6 串行（新赛道建议先 P0） | 依次读取 |

**单阶段进入的前置检查**：每个阶段文件声明了前置输入。缺失时先检查对应文件是否已存在（`Memory.md`、`study/01_*.md` 等）——存在则直接用，不存在则告知用户需要先补哪个阶段，或请用户提供等价信息，**不得凭空假设**。

**跳阶段**：P0、P4 可选；P5 在无任何变更源时可跳过；P6 永不可跳过。跳过 P1/P2 这类基础阶段时，必须确认用户已有等价信息。

## 通用执行约定

### 环境能力自适应

本技能只强依赖两件事：能对话、能读写文件。其余能力按下表降级，**不因缺工具而中断流程**：

| 所需能力 | 环境有 | 环境没有 |
|---------|--------|---------|
| 联网搜索/网页读取 | 强制联网核实，标注来源 | 明确声明"未联网核实"，关键事实标注【待核实】 |
| Shell/终端 | 直接执行并回读结果 | 输出完整命令块，请用户执行后回贴输出 |
| 子Agent 并行 | 自动派发并行子任务 | 单线程顺序执行，或生成自包含 Prompt 供用户多窗口执行 |
| docx/xlsx/pdf 转换 | 按«格式转换链»执行 | 交付 Markdown 源文件 + 转换指引 |

### 格式转换链（docx / xlsx 交付物统一走这里）

按顺序探测，用第一个可用的：

1. **专用技能**：环境中已安装 `minimax-docx` / `minimax-xlsx` 技能 → 按其规程执行
2. **pandoc**（docx）：`pandoc 输入.md -o 输出.docx`（中文文档建议加 `--reference-doc=模板.docx` 控制字体）
3. **Python**：docx 用 `python-docx`；xlsx 用本技能自带 `scripts/md_tables_to_xlsx.py`（依赖 openpyxl）
4. **全部不可用** → 交付 .md，并告知用户可用 Word/WPS 打开 md 或在线转换

### 门禁语义（🔴 GATE）

- 停下，列出待确认内容，等用户明确表态；**不得把"没回复"当默认同意**
- 用户说「继续 / OK / 确认」→ 下一阶段；给修改意见 → 改完重新过同一道门禁

### 项目状态记录（Memory.md 统一格式）

项目根目录维护 `Memory.md`（无则创建）。每阶段完成时追加：

```markdown
### [YYYY-MM-DD] requirements-pipeline/P[N] 完成
- **产出**：[文件相对路径]
- **关键决策**：[决策 + 理由]
- **待确认**：[遗留待确认项，无则写"无"]
```

## 质量红线（任何阶段不可违反）

1. **不臆造需求**：用户没说的功能不自行添加，标「待确认」
2. **不忽视约束**：预算、工期、团队配置是硬约束，所有方案必须在约束内
3. **不照搬参考**：参考平台功能必须过适配度评估（见 P4）
4. **不隐藏风险**：识别到的风险如实记录
5. **来源可追溯**：每个功能点标注来源（原始需求 / 参考平台 / 分析推导）
6. **版本可追溯**：文档标版本号，关键变更有说明
