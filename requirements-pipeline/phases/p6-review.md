# P6 自审与质控（不可跳过）

> **定位**：功能清单发客户前的最后一道质控门禁。4 视角审查 + 问题分级 + 修改建议。
> **产出**：`study/04_功能清单审查意见.md`

## 前置输入

- 最新版功能清单（`study/03_*_VN.md`，或跳过了 P4/P5 时的 `study/01_*.md`）
- `Memory.md` 项目约束（预算、工期、团队、客户级别）
- `references/estimation-baseline.md`（视角三的计算基准）

## 执行步骤

### Step 6.1 — 四视角审查

每个视角必须输出**具体问题**，禁止「看起来还行」。

**视角一：产品设计合理性**

- 功能冗余/重叠？（同一件事出现在两个模块？）
- 幽灵角色？（定义了但全清单没有它的功能点）
- 流程过重？（对客户体量来说节点太多？）
- 隐藏功能点遗漏？常见清单：编号/流水号生成规则 · 批量操作 · 数据导入（历史数据初始化）· 附件在线预览 · 操作引导/帮助 · 项目总览/台账 · 回收站/软删除 · 数据权限边界（谁能看谁的数据）

**视角二：技术落地可行性**

- 哪些功能复杂度被低估？
- 需要降级实现的功能？（全自动→半自动+人工调整；动态配置化→固定模板+扩展字段；在线编辑→上传下载修改）
- 可复用的模块？（如验收评审复用评审打分机制）
- P0 功能有技术卡点吗？

**视角三：预算范围匹配度**（用估算基准的健康度公式）

```
可用人天 = 团队人数 × 工期周数 × 5 × 0.8
单功能点均摊 = 可用人天 ÷ 功能点总数
< 1 人天/点 → ⚠️ scope 过大必须裁剪；1–2 正常；> 3 可上浮
```

超支时给出裁剪清单（按 P2 → P1 顺序裁，P0 不动）；并评估「参考补充」类的预期砍掉比例。

**视角四：组织适配度**（仅当做过 P4 对标）

- 参考平台功能是否匹配客户组织层级？有无照搬不适用项？
- 角色数量是否超出客户组织实际承载能力？

### Step 6.2 — 问题分级

| 级别 | 标记 | 定义 | 行动 |
|------|:---:|------|------|
| 阻断级 | ⚠️ | 不修正不能发客户 | 立即修改 |
| 重要级 | 🔶 | 建议修正后再发 | 优先修改 |
| 建议级 | 🔵 | 不阻塞，值得讨论 | 记录待议 |

### Step 6.3 — 修改建议汇总

按优先级排序的操作清单表（序号 / 具体操作 / 级别 / 状态）。

### Step 6.4 — 总体评价

2–3 段话覆盖：清单质量（结构/覆盖）· 核心风险（最大的坑）· 预算风险（功能量 vs 预算）。

### Step 6.5 — 输出

`study/04_功能清单审查意见.md`

## 后续行动

- ⚠️ 阻断级问题用户确认修改 → 回 P5 更新清单 → 可再跑一次 P6（迭代审查）
- 全部处理完 → 清单进入「可发送客户」状态，在 Memory.md 标记

🔴 GATE：输出问题统计（⚠️X / 🔶Y / 🔵Z）+ 阻断级明细，等用户决定修改或放行。
