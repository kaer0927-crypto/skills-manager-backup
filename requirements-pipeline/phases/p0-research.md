# P0 售前行业与竞品深度调研（可选）

> **定位**：在见客户收需求之前（尤其是陌生行业、新概念），做摸底扫盲与战略级研究。带着这份报告去聊需求，你就是内行。
> **产出**：`study/[研究对象]_横纵分析报告.md`（1 万字级，可转 PDF/HTML 交付）

## 前置输入

- 研究对象（行业 / 竞品 / 概念 / 公司），一句话说清"为什么要研究它"
- 无前置阶段依赖

## 方法委托与降级

本阶段方法论为**横纵分析法**（纵向历时叙事 + 横向竞对切面 + 交叉洞察）。

- **若环境已安装 `hv-analysis` 技能**（在技能目录中搜索 `hv-analysis/SKILL.md`）→ 完全按该技能规程执行，包括其自带的 PDF / HTML 转换脚本，本文件其余部分只作补充
- **若未安装** → 按下方内嵌精简规程执行，不得以"缺技能"为由降低产出标准

## 内嵌精简规程

### 1. 联网信息收集（有联网能力时为强制步骤）

- **禁止凭已有记忆盲写**。分两条线收集：纵向（起源、创始团队、发展节点、转折、危机）＋ 横向（竞品清单、各竞品口碑与差异、市场格局）
- 一手来源优先：官方博客 / 财报公告 / GitHub Release > 权威媒体原创 > 转载聚合；用户口碑找真实社区（知乎、Reddit、GitHub Issues）
- 有并行子 Agent 能力时，纵向线、横向线分两个子任务并行收集
- 自检：纵向能讲出完整故事吗？横向主要玩家有遗漏吗？关键事实有来源吗？不够就补搜
- **无联网能力时**：明确声明"以下基于模型已有知识，未联网核实"，所有关键数据标【待核实】，并列出建议用户人工核实的清单

### 2. 纵向分析（报告主体，6000–15000 字）

按时间轴还原研究对象从诞生到现在：起源背景 → 诞生节点 → 演进历程（版本/融资/转型/危机）→ 每个关键节点的**决策逻辑**（为什么选 A 不选 B）→ 自然分段（萌芽期/增长期/转型期）。
写成有因果的叙事故事，**不是年表流水账**。

### 3. 横向分析（3000–10000 字）

先判断竞品场景：**A 无直接竞品**（分析为什么没有、替代方案是什么，约 3000 字）/ **B 少量竞品**（逐一深挖）/ **C 竞品充分**（选代表性 3–5 个，每个 ≥1500 字）。
对比维度：技术路线、产品形态、目标用户、优劣势、定价体量；重点写清每个竞品"活成了什么样"、用户选它的真实理由，不要写成参数对照表。

### 4. 横纵交汇洞察（1500–3000 字，精华段）

回答五个问题：历史如何塑造当下位置？竞品的演变路径差异？今天的优势能追溯到哪个决策？劣势能追溯到哪个决策？未来三个剧本（最可能 / 最危险 / 最乐观），每个剧本要有逻辑支撑。

### 5. 写作禁区

- 禁套话（"首先其次最后""综上所述""值得注意的是"）、禁空洞词（"赋能""抓手""闭环"）、禁教科书开头（"在当今…时代"）
- 敢下判断，但先摆事实再给判断；推测明确标注"我的判断是"
- 搜不到的信息诚实标注【该信息暂缺】，**绝不编造**
- 用具体数字和细节代替概括（不写"快速增长"，写"从 X 到 Y"）

### 6. 报告结构

```
# [对象]_横纵分析报告
> 研究时间 | 所属领域 | 对象类型 | 编制：liuyz
一、一句话定义
二、纵向分析：从诞生到当下
三、横向分析：竞争图谱
四、横纵交汇洞察
五、信息来源（URL + 访问时间；未联网则为"待核实清单"）
```

## 输出与归档

1. 报告存 `study/[研究对象]_横纵分析报告.md`（无 study/ 目录则创建）
2. 格式转换按 SKILL.md«格式转换链»：hv-analysis 自带脚本 → pandoc → 交付 md
3. Memory.md 按统一格式追加 P0 完成记录

## 质检清单

- [ ] 纵向是叙事体，有因果逻辑，不是流水账
- [ ] 关键节点还原了决策逻辑，不只是"发生了什么"
- [ ] 横向场景判断正确（A/B/C），竞品分析够深
- [ ] 交汇洞察给出了新判断，不是前文缩写
- [ ] 全文 1 万字以上；关键事实有来源或标注【待核实】
- [ ] 未触犯写作禁区
