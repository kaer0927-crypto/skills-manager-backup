# P1 需求采集与结构化

> **定位**：把任意形式的原始客户需求（口头描述、会议记录、文档、截图）转成结构化项目概览，写入 `Memory.md`。这是流水线的起点。
> **产出**：`Memory.md`（项目概览 / 已确认事项 / 关键决策段落）

## 前置输入

- 用户提供的原始需求信息（任意形式）
- 无前置阶段依赖

## 执行步骤

### Step 1.1 — 信息采集清单

向用户逐项确认。未提供的标「待确认」，**不可自行假设**。

**⛔ 阻断项（缺失则不得进入 P2）**：

```
□ 核心业务：一句话说清系统要解决什么问题
□ 系统角色：有哪些角色，各自核心操作是什么（至少有轮廓）
□ 客户是谁：行业 / 单位级别 / 规模
```

**⚠️ 关键项（缺失不阻断 P2，但 P3 估算会不可靠，须在进 P3 前补齐）**：

```
□ 用户规模（注册数 / 日活 / 并发预估）
□ 年度业务量（核心实体的年度数量级）
□ 预算信号（明确金额或模糊区间）
□ 工期期望（硬截止或弹性）
□ 团队配置（几人开发）
```

**ℹ️ 完善项（可分批补齐）**：

```
□ 现有信息化基础（纯线下 / 有旧系统 / 部分线上）
□ 部署环境（公有云 / 私有化 / 政务云）
□ 交付模式（需求设计开发全包 / 只开发）
□ 硬性技术约束（信创 / 特定框架 / 特定数据库）
□ 移动端需求（本期是否需要）
□ 外部系统对接（对接哪些第三方）
□ 特殊合规要求（等保 / 电子签章 / 数据出境等）
```

采集策略：**先追问阻断项，一次最多问 5 个问题**，避免问卷式轰炸；其余项随对话自然补齐。

### Step 1.2 — 结构化写入 Memory.md

```markdown
## 项目概览

### [项目名称]
- **客户**：[客户名称]（[行业/级别/规模]）
- **核心需求**：[一句话]
- **功能模块**：[初步模块列表]
- **项目类型**：[B端/C端/政务/内部系统]
- **关键约束**：预算[?] | 工期[?] | 团队[?] | 部署[?] | 技术约束[?]

## 已确认事项（[日期]）
- [x] 事项 → 结论
- [ ] 待确认事项（标注为什么待确认、找谁确认）

## 关键决策
- 决策：理由
```

已有 Memory.md 则更新对应段落，不要重复创建。

### Step 1.3 — 完整性校验

| 检查项 | 状态 | 影响 |
|-------|:---:|------|
| 核心业务描述 | ✅/❌ | 缺失 → 阻断 P2 |
| 系统角色轮廓 | ✅/❌ | 缺失 → 阻断 P2 |
| 用户规模数量级 | ✅/⚠️ | 缺失 → P3 性能设计不可靠 |
| 预算信号 | ✅/⚠️ | 缺失 → P3 无法做预算匹配分析 |

## 交付物

- `Memory.md`（按上方格式新建或更新）

## 阻断规则

- 阻断项缺任何一个 → 主动追问，**不得进入 P2**，不得靠假设补齐
- 用户明确说"先按假设走"→ 可以继续，但每个假设在 Memory.md 中标【假设，待确认】

🔴 GATE：输出项目概览摘要 + 待确认清单，等用户确认后进入 P2。
