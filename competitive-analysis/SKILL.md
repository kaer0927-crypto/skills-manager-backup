# 竞品分析报告 Skill（深度战略级）

## 何时使用

当用户提出以下需求时触发：
- "分析 XXX 和它的竞品"
- "帮我做一份竞品分析报告"
- "对比 A、B、C 三家公司的产品"
- "对标 XX 产品"
- "做一份 XXX 行业格局分析"
- "competitive analysis on..."

## 工作语言

**默认中文**。当数据源（财报、英文报告、英文官网）是英文时，agent 内部可使用英文检索，但输出统一翻译/总结为中文。

## 用户必须提供的信息

skill 启动时**必须**向用户收集以下信息（缺一不可，否则提醒用户补全）：

1. **目标公司/产品**：要分析的主体（如 "飞书"）
2. **竞品列表**：1-5 家要对比的公司/产品（如 "钉钉、企业微信"）
3. **所属行业**：如未明确，agent 通过目标公司官网/报道推断
4. **分析重点**（可选）：用户最关心的维度（如 "B 端付费意愿"、"AI 能力"、"出海策略"）
5. **报告输出路径**（可选）：默认 `./competitive-analysis-{目标产品}-{YYYYMMDD}.md`

如果用户未提供目标公司和竞品列表，**必须**先追问，绝不直接开始。

## 工作流：8 阶段 Subagent 编排

整个流程通过 subagent 并行/串行协作完成，**相互校验/评审的 agent 完全独立**（不共享上下文、不共享会话状态）。

### 阶段 1：数据收集（5+ 个并行 subagent）

每个公司/产品由一个独立 subagent 负责，包括目标公司 + 每个竞品。

**Subagent Prompt 模板：**
```
你是【{公司名}】的独立调研员。请通过 WebSearch/WebFetch 收集以下信息：

1. 基础信息：成立时间、总部、创始人、团队规模、融资历史（轮次+金额+投资方）
2. 产品矩阵：核心产品线、目标用户、定价模式
3. 业务数据：DAU/MAU（如有披露）、付费用户数、ARR/营收（财报或公开报道）
4. 战略动态：近 12 个月重大发布、合作伙伴、并购、投资布局
5. 技术栈：公开的技术博客、招聘 JD 透露的技术方向、开源项目
6. 用户口碑：主要社区（G2、知乎、微博、X）的核心评价

输出要求：结构化 Markdown，每条事实标注【来源：URL】，区分"已确认"和"待验证"。

约束：只收集公开信息；遇到付费墙/数据缺失时明确标注"未公开"；不要编造数据。
```

**派发方式**：使用 Agent 工具，subagent_type="general-purpose" 或 "Explore"。

### 阶段 2：真实性校验（与阶段 1 完全独立的并行 subagent）

**关键原则：阶段 2 的 agent 不会读到阶段 1 agent 的会话历史，只拿到阶段 1 的输出文件**。每个 agent 从零开始验证。

**Subagent Prompt 模板：**
```
你是独立的事实核查员。你的任务是基于【原始数据收集报告】（见下方）
对【{公司名}】的所有事实做真实性校验。

【原始数据收集报告】
<阶段1的输出>

校验方法：
1. 对每条"已确认"事实，至少找 2 个独立来源交叉验证
2. 对"待验证"事实，明确判定：✓ 已证实 / ✗ 存疑 / ✗ 否认
3. 对财务/用户/团队等关键数据，使用专业渠道（披露易、SEC、Crunchbase、IT桔子）

输出格式：
| 事实 | 原始来源 | 验证来源 | 结论 |
|------|----------|----------|------|
| ... | ... | ... | ✓/✗ |

要求：保持怀疑态度，对存疑数据明确标注，不放过可疑数字。
```

### 阶段 3：行业综合分析（单个 subagent）

基于已校验的数据，进行行业层面分析。

**Subagent Prompt 模板：**
```
你是行业分析师。基于以下已校验的事实数据，撰写【{行业}】的行业分析：

<所有阶段1+阶段2的输出>

覆盖以下章节：
1. 产品价值：客户群体、痛点、解决方案、付费意愿
2. 环境成熟度：政策环境、商业环境
3. 标准化程度：标准化决定商业效率
4. 市场规模与趋势：现有市场规模、未来增长趋势（标注数据年份和来源）
5. 竞争态势：主要玩家及核心优劣势对比
6. SWOT 矩阵：行业层面

输出：结构化 Markdown，500-1000 字。
```

### 阶段 4：产品深度拆解（每个公司一个 subagent，并行）

**Subagent Prompt 模板：**
```
你是【{公司名}】的产品分析师。基于已校验事实数据，深度拆解该公司的产品：

<该公司阶段1+2的输出>

覆盖维度：
1. **定位**：核心定位、目标群体、核心产品/服务、定位演变历史
2. **核心竞争策略**：优势/挑战、与竞品的定位差异、定位方面建议
3. **能力**：创始人背景、团队基因、技术能力、服务能力（强调独特性）
4. **资源**：数据资产、融资能力、标杆客户、战略合作（强调稀缺性）
5. **场景/体验**：核心功能覆盖的业务场景、解决的痛点、差异化点
6. **用户体验**：用户效率与感受、做得好的/不好的地方

输出：结构化 Markdown，每个论点都要有事实支撑。
```

### 阶段 5：财务/团队/技术栈深度对比（2-3 个独立 subagent）

这是战略级独有的深度维度。3 个独立 agent 互不知晓彼此。

- **Subagent A - 财务分析师**：对比所有公司的融资历史、估值、营收、付费模式、商业化效率
- **Subagent B - 团队/组织分析师**：对比创始人背景、核心团队、组织规模、招聘节奏
- **Subagent C - 技术分析师**：对比技术栈、开源贡献、技术博客、专利、AI 投入

**关键：3 个 agent 完全独立工作，最后由主 agent 整合。**

### 阶段 6：报告转写（单个 subagent）

将所有分析整合为最终报告。**严格遵循 references/template.md 模板**。

**Subagent Prompt 模板：**
```
你是报告撰写人。基于以下所有分析材料，按【references/template.md】模板
撰写最终竞品分析报告。

材料：
- 阶段3：行业分析
- 阶段4：所有公司产品拆解
- 阶段5：财务/团队/技术对比

要求：
1. 严格按模板结构，不漏章节
2. 保留所有事实来源标注
3. 总长度 8000-15000 字
4. 中文输出
5. 引用财务/数据时使用脚注或括号注明来源
```

### 阶段 7：多视角独立评审（3 个并行 subagent，关键！）

3 个 agent **完全独立**，互不读取彼此评审意见，每人都从头读完整报告。

- **Subagent α - 战略评审员**：从战略视角评估报告——观点是否清晰、建议是否可执行、是否漏掉关键战略问题
- **Subagent β - 数据审计员**：从数据准确性评估——所有数据是否标注来源、是否有可疑数字、SWOT 是否平衡
- **Subagent γ - 商业可行性评审员**：从商业视角评估——建议是否可落地、机会识别是否真实、风险是否充分

**Subagent Prompt 模板（每个视角单独使用）：**
```
你是【{视角}】独立评审员。请评审以下竞品分析报告：

<报告全文>

评审清单见 references/review-checklist.md

输出格式：
1. 总体评分（1-10）
2. 必须修改的问题（按严重性排序）
3. 建议优化的地方
4. 做得好的地方
```

### 阶段 8：报告修改（单个 subagent）

整合 3 个评审 agent 的意见，修改报告。

**Subagent Prompt 模板：**
```
你是报告编辑。基于以下 3 份独立评审意见，修改竞品分析报告：

报告原文：<阶段6输出>
评审意见α（战略）：...
评审意见β（数据）：...
评审意见γ（商业）：...

修改原则：
1. 3 个评审都提到的问题 → 必须修改
2. 2 个评审提到的问题 → 应该修改
3. 1 个评审提到的 → 酌情修改
4. 保留所有事实证据
5. 输出【修改说明】章节，列出本次修改了哪些地方、为什么
```

## 独立性保证机制

为确保校验/评审 agent 的独立性：

1. **会话隔离**：每个 Agent 调用是全新会话，不共享上下文历史
2. **数据传递通过文件**：阶段 1 的输出写入临时文件，阶段 2 的 agent 只读该文件，不知道阶段 1 的思考过程
3. **Prompt 显式强调**："你是独立的事实核查员，不要预设任何结论，对存疑数据要明确指出"
4. **多视角评审分散**：3 个评审 agent 使用不同的 subagent_type 分散决策

## 输出文件

最终交付：
```
{用户指定路径}/competitive-analysis-{目标产品}-{YYYYMMDD}.md
```

报告应包含：
- 行业分析（5 个子章节 + SWOT）
- 每家公司的产品拆解（6 个维度）
- 财务/团队/技术栈对比（3 个表格）
- 综合结论（借鉴机会、机会识别、战略建议）
- 修改说明（最后阶段产出）
- 引用来源汇总
