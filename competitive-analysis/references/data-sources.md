# 数据来源指南

本文件是 `competitive-analysis` skill 阶段 1 数据收集 agent 的参考指南。所有 subagent 在收集数据时**必须**按本指南的渠道优先级和方法论执行。

---

## 渠道分类

### A. 官方渠道（优先级最高）

| 类型 | 渠道 | 适用数据 |
|------|------|----------|
| 公司官网 | 官网首页、产品页、关于我们 | 定位、团队、产品矩阵、最新动态 |
| 官方公告 | 官方公众号、官方微博、Newsroom | 战略动态、合作伙伴、重大发布 |
| 财报披露 | 披露易（hkexnews）、SEC EDGAR、巨潮资讯、腾讯财经、新浪财经 | 营收、利润、用户数、战略规划（限上市公司） |
| 监管文件 | 反垄断申报、IPO 招股书、年报 | 业务结构、关联交易、风险因素 |
| 招聘信息 | 拉勾、Boss直聘、LinkedIn、官网招聘页 | 团队规模、组织结构、技术栈、薪资水平 |

| 数据库 | 适用对象 | 数据类型 |
|--------|----------|----------|

| CB Insights | 全球科技公司 | 行业格局、并购记录 |

### C. 专业媒体（深度分析）

## 数据收集方法论

### 步骤 1：基础信息扫描

每个公司从 4 个数据点开始：
1. **成立时间与创始人**（企查查/Crunchbase/官网）
2. **核心产品定位**（官网首页一句话）
3. **最近一轮融资**（IT桔子/Crunchbase）
4. **最新用户/营收数据**（财报/官方公告）

### 步骤 2：分层深入

按 **业务 → 产品 → 用户 → 财务 → 团队 → 技术** 顺序逐层深入。

### 步骤 3：交叉验证

- 每条关键事实**至少 2 个独立来源**
- 优先级：官方 > 数据库 > 媒体 > 通用搜索
- 当多个来源冲突时，优先官方/财报/招股书

### 步骤 4：标注置信度

每条事实标注：
- **【已确认】**：2+ 来源一致
- **【单源】**：仅 1 个来源
- **【存疑】**：来源冲突
- **【未公开】**：未找到可信来源

## 不同类型数据的最佳渠道

### 营收 / ARR / 利润
- 上市公司：财报
- 未上市：Crunchbase、IT桔子、行业报告推算
- 替代指标：员工数 × 人均产值估算

### 用户数 / DAU / MAU
- 财报披露
- 官方公告
- 第三方监测：QuestMobile、Sensor Tower、SimilarWeb

### 市场份额
- 行业研究报告：IDC、Gartner、艾瑞、QuestMobile
- 注意：报告定义的口径差异

### 团队规模
- 招聘 JD 总数 + 估算
- LinkedIn 员工数
- 官方披露

### 融资历史
- Crunchbase / IT桔子 / 企查查
- 投资方官方公告
- 36Kr / 晚点深度报道

### 技术栈
- 招聘 JD（最直接）
- 技术博客（如 engineering.{company}.com）
- GitHub 开源组织
- 专利数据库

## 数据缺失处理

当某个数据点**完全无法找到**：
1. 明确标注"未公开"
2. 给出"为什么找不到"的合理推测（如：未上市、不愿披露、商业敏感）
3. **绝对不要编造数字或编造来源**

当数据**部分缺失**：
1. 给出可信区间（如"营收估算 10-30 亿元"）
2. 标注估算方法和不确定性

## 反向验证清单

为防止信息错误，每条引用必须自检：
- [ ] 来源 URL 真实可访问
- [ ] 发布时间在合理时间窗口
- [ ] 引用上下文与原文一致
- [ ] 没有断章取义
- [ ] 没有过时数据被误用为最新数据

---

## 关键提示

> **写实胜于完美**：宁可明确"未公开"，也不要编造数据。
> **多源胜于单源**：单源数据标注"【单源】"，提示后续校验 agent 重点核查。
> **新近胜于陈旧**：用户行为/技术栈/团队数据用最近 6 个月内的。
> **官方胜于第三方**：争议时官方为准。
