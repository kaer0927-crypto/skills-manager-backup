# 评审清单

本文件是 `competitive-analysis` skill 阶段 7 多视角独立评审 agent 的检查清单。三个评审 agent（战略 / 数据 / 商业可行性）从不同视角使用本清单。

---

## 共同评审原则

1. **保持怀疑**：不要预设报告是正确的，每条主张都要审视
2. **证据导向**：质疑每个数据/结论的证据是否充分
3. **结构审视**：报告结构是否完整、是否漏章节
4. **可执行性**：建议是否真的可执行
5. **客观性**：是否存在过度吹捧某家公司或过度贬低某家公司的偏见

---

## 评审维度 α：战略视角

### 检查项

#### A. 战略观点
- [ ] 报告对竞争格局的判断是否清晰
- [ ] 是否识别了行业的关键战略变量（技术、政策、用户行为）
- [ ] 对各家公司的战略定位是否描述准确
- [ ] 是否遗漏了关键战略玩家

#### B. 战略建议
- [ ] 战略建议是否具有差异化（不是泛泛而谈）
- [ ] 建议是否考虑了竞品可能的反击
- [ ] 建议的优先级是否合理
- [ ] 是否给出了"不做什么"的反向建议

#### C. 战略前瞻
- [ ] 是否分析了未来 12-24 个月的战略走向
- [ ] 是否识别了潜在的颠覆性变量（如 AI 带来的机会）
- [ ] 是否考虑过生态战/平台战/单点突破的不同路径

- 战略格局清晰度：____
- 战略建议可执行性：____
- 战略前瞻性：____
- 整体战略洞察力：____

## 评审维度 β：数据准确性

### 检查项

#### A. 来源标注
- [ ] 每条数据是否标注了来源
- [ ] 来源 URL 是否真实可访问
- [ ] 关键数据是否标注了发布时间
- [ ] 是否区分了"已确认"和"待验证"

#### B. 交叉验证
- [ ] 关键数据是否有 2+ 独立来源
- [ ] 财务/用户/团队数据是否来自权威渠道（财报/Crunchbase）
- [ ] 是否存在过时数据被误用为最新数据
- [ ] 估算数据是否明确标注"估算"和估算方法

#### C. 数字一致性
- [ ] 报告内前后数字是否一致（如某公司同时说营收 10 亿和 30 亿）
- [ ] 表格与正文描述是否一致
- [ ] 比例/百分比计算是否正确
- [ ] 是否存在可疑的"四舍五入"模糊数字

#### D. 平衡性
- [ ] SWOT 矩阵是否平衡（避免一边倒）
- [ ] 优劣势分析是否客观
- [ ] 是否有数据被刻意放大或缩小

- 来源完整性：____
- 交叉验证充分性：____
- 数字准确性：____
- 整体数据可信度：____

## 评审维度 γ：商业可行性

### 检查项

#### A. 机会识别
- [ ] 报告识别的机会是否真实存在（不是凭空想象）
- [ ] 机会窗口期是否合理（不是 5 年后的远期幻想）
- [ ] 是否区分了"机会"和"理想"
- [ ] 机会是否考虑到竞品已经在做的

#### B. 建议可落地性
- [ ] 战略建议是否可落地（人/钱/时间/能力是否到位）
- [ ] 建议的预期效果是否可衡量
- [ ] 建议是否考虑了执行风险
- [ ] 是否给出了具体的执行路径

#### C. 风险评估
- [ ] 是否充分识别了风险
- [ ] 风险是否给出了缓解方案
- [ ] 是否考虑了"黑天鹅"事件
- [ ] 风险分析是否过于乐观或过于悲观

#### D. 商业逻辑
- [ ] 商业模式的分析是否合理
- [ ] 付费意愿/付费能力的判断是否有依据
- [ ] 商业化效率的对比是否合理
- [ ] 是否考虑到了单位经济模型（unit economics）

- 机会真实性：____
- 建议可落地性：____
- 风险评估充分性：____
- 整体商业洞察：____

## 必须修改的问题分类

### P0 - 严重（必须修改）
- 关键数据错误
- 战略判断明显失实
- 引用来源造假或不可访问
- 报告结构严重残缺
- 战略建议方向性错误

### P1 - 重要（应该修改）
- 关键数据未标注来源
- 多个数据相互矛盾
- 建议过于空泛无法执行
- 风险评估明显不足
- SWOT 矩阵严重失衡

### P2 - 优化（建议修改）
- 表述不够清晰
- 个别数据时效性不够
- 章节内部逻辑可以更紧凑
- 案例引用可以更具体

### P3 - 锦上添花
- 排版/格式细节
- 词汇选择
- 引用格式

## 评审输出格式

每个评审 agent 必须按以下格式输出：

```markdown
# 评审报告：{视角}（α/β/γ）

## 总体评分：___/10

## P0 必须修改的问题
1. {问题描述} - 出现在第 X 节"原文" - 修改建议
2. ...

## P1 重要修改
1. ...

## P2 优化建议
1. ...

## 做得好的地方
- ...

## 评分细节
- {维度 1}：___/10
- {维度 2}：___/10
- {维度 3}：___/10
- {维度 4}：___/10
```

---

## 独立性要求

> **重要**：三个评审 agent 必须完全独立工作：
> - 不要相互读取对方的评审意见
> - 不要预设其他 agent 的结论
> - 即使觉得"已经有人提过这个"，也要独立写出来
>
> 这样阶段 8 的修改 agent 才能根据"多个 agent 都提到的问题 = 重要问题"做优先级判断。
