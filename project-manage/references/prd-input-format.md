# PRD 输入格式参考

> 本文件作为 `project-manage` Skill 解析输入 PRD 的格式参考。**输入 PRD 不一定是这个格式**，本文件用于辅助 Skill 识别结构、抽取关键信息；当 PRD 结构差异较大时，按"四、需求功能清单"+"五、需求功能详述"为核心进行启发式解析。

---

## 标准 PRD 模板

```markdown
# <PRD 标题>

## 一、需求背景
描述当前面临的问题或机会。

## 二、需求目标
本次项目的核心目标（具体、可衡量）。

## 三、需求核心业务流程图
（Mermaid 业务流程图）

## 四、需求功能清单

| 终端 | 模块 | 功能 | 描述 |
|------|------|------|------|
| 业主小程序 | 首页 | banner轮播 | 展示促销活动 Banner，支持点击跳转 |
| 业主小程序 | 首页 | 限时秒杀 | 展示秒杀活动商品 |
| 后台管理 | 营销管理 | 活动配置 | 配置秒杀活动规则与商品 |
| 后端 | 营销服务 | 活动查询 | 提供活动列表/详情接口 |

## 五、需求功能详述

#### 5.1 <终端>——<模块>——<功能名称>
**原型描述**：...
**用户故事**：作为[角色]，我想要[操作]，以便于[价值]。
**前置条件**：...
**核心逻辑**：...
**边界条件与异常处理**：...
**技术难点分析**：...   ← 关键：用于风险备注
**验收标准**：成功/校验/异常场景
**测试用例**：（MECE，每条≤20字）
```

---

## PRD → 项目管理表映射规则

| PRD 来源 | 映射到项目管理表 | 说明 |
|----------|------------------|------|
| 功能清单表（终端/模块/功能） | 拆解为开发子任务，按模块分组 | 每条功能 ≈ 1 个开发子任务 |
| 功能数量、模块复杂度 | 作为工期估算依据 | 见 `scheduling-rules.md` |
| 技术难点分析 | 写入对应任务「备注」列 | 提示风险 |
| 验收标准 / 测试用例 | 支撑「测试用例评审」「测试完成」里程碑工期 | 见 `scheduling-rules.md` |
| 业务流程图 / 需求目标 | 辅助判断整体规模与阶段划分 | 仅作为辅助，不直接生成任务 |
| 涉及终端（小程序/后端等） | 辅助识别负责角色 | 前端→前端开发；后端→后端开发 |

---

## 启发式解析规则（应对非标准 PRD）

1. **功能清单识别**：查找包含「终端」「模块」「功能」「描述」4 列的 Markdown 表格
2. **技术难点识别**：在「五、需求功能详述」中搜索「技术难点」「风险」「难点」等关键词
3. **终端推断**：从「功能描述」「用户故事」中识别「业主小程序」「门店 APP」「后台」「后端」「服务端」等关键词
4. **角色推断**：根据终端类型推断负责人角色（默认规则见 SKILL.md "输入约定"）
5. **范围识别**：从「需求目标」「验收标准」中提取核心范围关键词

---

## 不强制要求

- 输入 PRD 不必完全符合上述模板
- 「四、需求功能清单」表格列名可略有差异（如「菜单/能力」代替「功能」）
- 「五、需求功能详述」可简化为只含「用户故事」+「验收标准」
- 缺失信息统一标注「待补充」，**不得自行臆造**
