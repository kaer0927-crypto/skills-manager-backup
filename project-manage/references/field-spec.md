# 项目管理表字段说明

> 本文件定义 `project-manage` Skill 输出表格的字段语义、填写规则与示例。

---

## 字段定义（9 列，固定顺序）

| # | 字段 | 含义 | 填写规则 | 示例 |
|---|---|---|---|---|
| 1 | **任务/子任务** | 任务的具体名称 | 里程碑任务用里程碑名；开发子任务用「<终端>-<模块>-<功能>」 | `需求评审` / `业主小程序-首页-banner轮播` |
| 2 | **所属阶段/里程碑** | 任务所属的阶段或里程碑 | 里程碑任务填写里程碑名；开发子任务填写所属里程碑 | `需求评审阶段` / `开发提测阶段` |
| 3 | **负责人/角色** | 任务负责人或负责角色 | 按终端/任务类型推断；未确认标「待补充」 | `产品经理` / `前端开发` / `QA` |
| 4 | **开始时间** | 任务计划开始日期 | 格式 `YYYY-MM-DD`；未排期标「待排期」 | `2026-07-10` |
| 5 | **结束时间** | 任务计划结束日期（含） | 格式 `YYYY-MM-DD`；未排期标「待排期」 | `2026-07-12` |
| 6 | **预估工期** | 任务持续天数（自然日或工作日） | 整数 + 单位（默认自然日）；里程碑任务可填写 `1d` | `3d` / `1d` / `待补充` |
| 7 | **依赖关系** | 前置任务名（多个用 `,` 分隔） | 必须能在表中找到对应前置任务；无前置填「-」 | `-` / `需求评审` / `开发提测,测试用例评审` |
| 8 | **状态** | 任务当前状态 | 默认「未开始」 | `未开始` / `进行中` / `已完成` |
| 9 | **备注** | 风险、说明、补充信息 | 技术难点、未确认项、假设 | `技术难点：需对接微信支付分账接口` |

---

## 字段填写规则详解

### 1. 任务/子任务

- **里程碑任务**：使用 10 项核心里程碑的标准名称
- **开发子任务**：`<终端>-<模块>-<功能>` 三段式命名，便于追溯 PRD 功能清单
- **测试/UI 子任务**：`<任务类型>-<模块或对象>`，如 `UI设计-首页`

### 2. 所属阶段/里程碑

与 10 项核心里程碑对应（详见 `milestone-def.md`）：
- 需求评审阶段
- 技术方案评审阶段
- UI 评审阶段
- 测试用例评审阶段
- 开发提测阶段
- 测试完成阶段
- 验收完成阶段
- 发版上线阶段
- 生产验证阶段
- 业务培训阶段

### 3. 负责人/角色

默认角色映射（按终端/任务类型推断）：

| 任务类型 | 默认角色 |
|---|---|
| 需求评审 / 验收完成 / 业务培训 | 产品经理 |
| 技术方案评审 | 技术负责人 / 架构师 |
| UI 评审 | UI 设计师 |
| 测试用例评审 / 测试完成 | QA |
| 开发提测（前端） | 前端开发 |
| 开发提测（后端） | 后端开发 |
| 发版上线 | 运维 / 发布工程师 |
| 生产验证 | 运维 + 产品经理 |

未确认的实际人员，标「待补充」。

### 4. 开始时间 / 结束时间

- 格式：`YYYY-MM-DD`
- 未提供起始日时，整列标「待排期」
- 结束时间 ≥ 开始时间
- 后置任务的开始时间 ≥ 前置任务的结束时间

### 5. 预估工期

- 单位：`d`（天，自然日）
- 默认使用自然日估算（含周末）；如需工作日估算请在 SKILL 调用时声明
- 估算依据见 `scheduling-rules.md`

### 6. 依赖关系

- 无前置填 `-`
- 多个前置用 `,` 分隔：`任务A,任务B`
- 必须能在表中找到对应任务行；**禁止引用不存在的任务**
- **禁止循环依赖**

### 7. 状态

固定取值：`未开始` / `进行中` / `已完成` / `已阻塞`
- **默认「未开始」**

### 8. 备注

- 技术难点摘要：写入对应开发子任务
- 风险提示：工期风险、依赖风险、资源风险
- 未确认事项：标「待确认：<具体内容>」

---

## 禁止出现的字段

以下字段**不允许**出现在项目管理表中：

- ❌ **优先级**：项目内已通过里程碑排序表达优先级
- ❌ **进度百分比**：状态字段已表达进度
- ❌ **工时（人天）**：预估工期已表达工作量
- ❌ **备注之外的自由文本字段**

|---|---|---|---|---|---|---|---|---|
