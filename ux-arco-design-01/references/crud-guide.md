# 数据列表 CRUD 规范（增删改查）

> 基于模板 `list-search-table.js`（ProTable 主范式）的真实交互提炼，适用于所有数据列表页面。
> 核心原则：**新增/编辑用弹窗表单 + 回填 + 校验；删除/批量删除用确认弹窗（danger）；每个操作后 Toast 反馈 + 重查列表**。

## 操作列（每行的编辑/删除）

- 操作列固定在表格最右，按钮用**文本按钮**：编辑（普通色）+ 删除（`status: danger` 红色文本）
- 删除按钮必须红色（danger），与编辑视觉区分
- **列宽要按按钮数算，不能拍脑袋给 120px**：`a-table-column` 的 `width` 含 16px×2 的单元格内边距，两个文本按钮就需要 **≥160px（实测 140px 会折行）**，推荐 180px。
- 操作列放 3 个及以上动作时，前两个直接显示、其余收进 `a-dropdown`（「更多」），不要拉宽到 260px 挤占数据列。
- 单元格默认允许换行，一旦折行整行高度会被撑到 80px+，破坏 40–48px 行高节奏。落地时给操作列加 `align="center"`（或 right）并确保单行，必要时对操作区加 `white-space: nowrap`。

## 序号列（跨页连续）

分页表格的序号不能直接用 `rowIndex + 1`，否则每页都从 1 开始。官方 Arco Pro 的写法：

```vue
<a-table-column title="序号" :width="80" align="center">
  <template #cell="{ rowIndex }">
    {{ rowIndex + 1 + (pagination.current - 1) * pagination.pageSize }}
  </template>
</a-table-column>
```

- 用 `columns` 数组式时写 `{ title: '序号', dataIndex: 'index', slotName: 'index' }` + `<template #index="{ rowIndex }">`。
- 序号列宽 72–80px，居中；不要给它排序能力。

## 新增（Create）

1. 工具栏左上角放「新增」按钮（primary，实底主色）
2. 点击打开**弹窗表单**（Modal，尺寸按主题弹窗规范：440px，字段多可 560px）
3. 表单初始为空，打开时**清空上一次校验状态**（clearValidate）
4. 保存流程：校验表单 → 校验通过后按钮进入 loading（saving）→ 提交成功 → Toast 成功提示（如「新增成功」）→ 关闭弹窗 → **回到第 1 页重查列表**
5. 校验失败：红环 + 字段错误短句（见主题表单规范），不关闭弹窗

## 编辑（Update）

1. 点击行内「编辑」→ 打开同一弹窗表单（与新增共用），**表单回填该行数据**（id 隐藏携带）
2. 弹窗标题切换：新增态「新增 XX」/ 编辑态「编辑 XX」
3. 保存流程同新增：校验 → loading → 提交成功 Toast（如「更新成功」）→ 关闭弹窗 → 重查列表
4. 若详情面板（抽屉/详情区）正展示该行，更新后**同步刷新详情内容**
5. 保存成功后回到**当前页**（编辑不跳页；新增才回第 1 页）

## 删除（Delete）

1. 点击行内「删除」→ 先弹**确认弹窗**：
   - 标题「删除」，正文「确定删除该条记录？」，确认按钮文案「删除」且 `status: danger`，取消「取消」
2. 确认后：删除 → Toast 成功提示（如「删除成功」）→ 重查列表
3. **删空回退页码**：若当前页删完后该页无数据且不是第 1 页，页码自动回退一页再刷新，避免空页
4. 若详情面板正展示该行，删除后**关闭详情**

## 批量操作（Batch）

1. 表格开启行勾选（checkbox），工具栏放「批量删除」等批量按钮
2. **未勾选任何行时批量按钮禁用**（disabled）；勾选后启用
3. 点击批量删除 → 确认弹窗（标题「批量删除」，正文说明将删除 N 条，确认按钮 danger）→ 删除 → Toast 提示「删除成功（N 条）」→ 重查列表
4. 页码回退规则同单删：当前页数据被删空则回退一页
5. **部分成功必须单独处理**：批量接口返回逐条结果时，不能只弹一句「操作成功」。失败行要能定位（行号/主键/名称 + 失败原因），并提供「重试失败项」与「导出失败明细」。完整的三种结果形态见 [feedback-patterns.md](feedback-patterns.md)「批量操作：必须处理部分成功」。

## 查询 / 分页（Read）

1. 筛选区按「筛选区布局」规范（一行 6 字段栅格，按钮同行）
2. 表格底部固定分页条：共 X 条 · 当前第 N 页 · 每页条数可选（默认 10 条/页，支持切换）
3. 分页变化（翻页/改每页条数）触发重查，不重置筛选条件
4. 详情查看：行点击或「查看详情」按钮 → 打开右侧抽屉/详情面板（左列表右详情用 list-master-detail 骨架）

### 筛选状态持久化（可分享链接）

筛选条件不能只活在组件内存里。用户把链接发给同事、刷新页面、从详情页返回，都应该回到同一批数据。

- **落 URL**：筛选、排序、分页、页签都写进 `route.query`，字段名用业务语义（`status=paid&owner=u_1024`），不要用 `f1/f2`。
- **写时机**：点「查询」时整体替换（`router.replace`，不产生历史堆积）；输入框打字过程不写，避免历史记录被刷爆。
- **读时机**：`onMounted` 从 query 还原，非法值回落默认并静默纠正（不要弹错），空条件不写空串。
- **数组与区间**：多选用重复 key 或逗号分隔（团队内统一一种），区间用 `start/end` 两个字段，避免嵌套对象被 URL 编码成一坨。
- **分页**：`page`、`pageSize` 一并入 URL；删除导致页码回退时同步更新 URL，避免刷新后又跳回空页。
- **敏感值**：不要把手机号、身份证等放进 query（会进浏览器历史与日志），这类筛选用 POST 或只存 session。

```ts
const syncQuery = () => {
  const next = { ...route.query, ...pick(filters, activeKeys), page: pager.current, pageSize: pager.pageSize }
  Object.keys(next).forEach((k) => (next[k] === '' || next[k] == null) && delete next[k])
  router.replace({ query: next })
}
```

### 保存为常用视图

筛选用得频繁时（客服、运营、财务对账），提供「保存当前筛选」而不是让用户每次重选。

- **入口**：筛选区按钮组右侧「保存视图」，次级按钮样式；已选视图在筛选区上方以 `a-tag` 展示，可切换、可重命名、可删除。
- **存什么**：筛选条件 + 排序 + 列显隐（不含分页，分页每次从第 1 页开始）。
- **存哪**：个人视图存后端（跨设备）或 `localStorage`（轻量原型）；团队公共视图必须后端存储并带权限。
- **命名**：默认「未命名视图」，保存时要求填写；同名覆盖要二次确认。
- **上限**：个人视图建议 ≤10 个，超出提示删除；不要把下拉塞成几十条。
- **失效兜底**：视图里的字段被下线或选项被删除时，忽略该项并在切换后提示「部分条件已失效」。
- **与 URL 的关系**：切换视图 = 用视图内容重写 URL query，两者不各存一份状态。

## 导出（Export）

1. 工具栏放「导出」按钮（outline/secondary），紧跟批量操作之后
2. 导出动作：选择导出格式（**CSV / XLSX** 二选一）→ 确认导出 → 按钮进入导出中状态（exporting，loading）→ 成功 Toast（如「导出成功，共 N 条」）
3. 导出范围与当前筛选/勾选一致；导出中防重复点击
4. 完成后可提供下载入口（如「账单导出任务已完成，可下载」通知/按钮）
5. **含敏感字段的导出**必须二次确认（导出范围 + 字段 + 用途），并记录操作人、时间、条数；脱敏列是否允许导出原值由后端判定，详见 [data-security.md](data-security.md)「导出」。

## 行内编辑模式（list-editable）

1. 行内编辑：点击行内「编辑」→ 该行字段变输入控件（input/select），行尾提供「保存」「取消」
2. 保存：单行保存（saveRow）Toast「保存成功」；顶部「保存全部」批量保存（saveAll）Toast「已保存全部修改」
3. **未保存警告**：存在未保存修改时切换行/离开页面/批量操作，先弹确认（savedWarn「存在未保存的修改」），防丢失
4. 行内编辑与批量删除可共存（勾选 + 批量删除按钮）

## 反馈与刷新通则

- 所有操作成功必有 Toast 反馈（顶中、主题柔影）
- 所有写操作（增/删/改/批量）后必**重查列表**，保证数据一致
- 失败场景：校验失败红环提示；提交失败 Toast 错误提示并保持弹窗
- 保存按钮在提交期间 loading，防止重复提交
- **行按钮的显示与禁用不在这里拍脑袋**：由 [state-machine.md](state-machine.md) 的「状态 → 动作」矩阵推导，禁用必须有原因
- **耗时操作按分档给反馈**：<1s 直接刷新；1–3s 按钮 loading；>3s 进度 + 任务中心；>30s 转通知。空态分四类、部分成功、409 冲突见 [feedback-patterns.md](feedback-patterns.md)
- **导出/查看原值等敏感动作**走 [data-security.md](data-security.md) 的确认与留痕

## Arco 落地要点（实现层，必须照做）

1. **删除确认**：`Modal.confirm({ okButtonProps: { status: 'danger' }, onBeforeOk: async (done) => { … done(true) } })`。
   `danger: true` 与 `onOk` 在 Arco 中不存在/不会给按钮 loading，写错会导致“可重复点击删除”。
2. **批量选择**：`:row-selection="{ type: 'checkbox', onlyCurrent: true }"` 默认只全选当前页；
   需要跨页批量时改用受控 `:selected-keys` + `@selection-change`，并在工具栏显式提示“已选 N 条（跨页）”。
3. **删空回退**：Arco 分页的 `auto-adjust` 只处理“改每页条数”，**不处理删空**；必须自行实现：删除 → 重查 → 若 `rows.length === 0 && current > 1` 则 `current--` 再查一次。
4. **新增回第 1 页**：`pager.current = 1` 后再 `fetchList()`；编辑保持 `current` 不变。
5. **列表重查**：统一封装 `fetchList()`，所有写操作成功后只调它，禁止局部 splice 造成总数与分页不一致。
6. **汇总行**：金额/数量类列表用 `summary` + `#summary-cell` 展示合计，避免用户在导出前自己加总。
7. **导出**：Arco 无导出组件，按钮态用 `loading` 防重复；导出接口返回任务 ID 时，用 `Notification` 提供下载入口。

## 自查清单（产出后逐条过）

1. 操作列编辑/删除按钮齐全，删除为红色文本按钮？
2. 新增/编辑共用弹窗表单，编辑能回填该行数据、标题能区分增/改？
3. 删除/批量删除都有 danger 确认弹窗，未勾选时批量按钮禁用？
4. 每个写操作后都有 Toast + 重查列表；删空回退页码？
5. 分页条完整（总数/页码/每页条数）且操作后页码正确？
6. 筛选/排序/分页是否写进 URL，刷新与分享后能还原？
7. 高频筛选是否提供「保存为常用视图」，切换视图是否与 URL 同一份状态？
8. 批量与导入是否处理部分成功，失败行能否定位并重试？
