# 模板：系统泳道图 ASCII 草图（swimlane）

> 适用图类型：**系统泳道图** —— 按角色 / 系统划分泳道，跨泳道协作流程。
> 视觉风格：**纵向泳道**（泳道左右并列成"竖条"，每条泳道内步骤上下堆叠） + **黑白配色**（无填色，仅黑色边框）。
> 引用方：SKILL.md 步骤 2。

## 二、填写说明

| 元素 | 填写要求 |
|---|---|
| 泳道数量 | **不限制**（2、3、4、N 都可）；推荐 2-5 条，>5 条建议拆图 |
| 泳道方向 | **纵向**（左右并列成竖条状），每条泳道内步骤**上下堆叠** |
| 泳道命名 | 写"角色"（用户/客服/管理员）或"系统"（客户端/服务端/支付网关），不混搭 |
| 泳道衔接 | **无缝衔接**：泳道与泳道之间不留间隙（ASCII 中用单空格 `│ │` 紧邻，不要用 `│   │` 多空格） |
| 步骤归属 | 步骤所在泳道 = 该步骤的执行方；跨泳道用箭头连 |
| 编号 | 步骤必须编号 1、2、3...，便于按时间读 |
| 同步 vs 异步 | 实线 = 同步请求；虚线 / 标注 async = 异步消息 |
| 异常路径 | 失败/重试跨泳道时显式画"失败返回"虚线箭头 |
| 配色 | **黑白风格**，ASCII 草图无颜色 |

## 三、ASCII 排版约定（纵向泳道）

```
┌────────┐ ┌────────┐ ┌────────┐
│ 泳道1  │ │ 泳道2  │ │ 泳道3  │   ← 顶部写泳道名
│        │ │        │ │        │
│┌──────┐│ │        │ │        │   ← 步骤小框写在泳道内
││1.步骤││ │        │ │        │
│└──┬───┘│ │        │ │        │
│   │    │ │  ▼     │ │        │   ← 上下用 │ + ▼ 表示流向
│   ├───▶│ │┌──────┐│ │        │
│        │ ││2.步骤││ │        │
```

每条泳道宽 8 字符（泳道框）+ 步骤内框宽 6 字符（左右各 1 边距）。

**无缝衔接规则**：泳道与泳道之间**只留 1 字符间隔**（`│ │` 紧邻），不允许多空格（`│   │`）。这对应 drawio XML 中"子泳道 x 坐标紧密相接、外层大泳道 width = 子泳道 width 之和"的设计。

**y 坐标对齐规则（关键）**：跨泳道顺序相邻的节点 y 坐标尽量对齐（即同一条水平线），让跨泳道连边画成水平线；同泳道内的串行节点 y 不同（垂直堆叠表示时间顺序）。

**层级 y 间距约定**：每两个相邻层级间隔约 140-180 像素（建议 60 → 240 → 400 → 540 ...），同一层级内可有多个节点。

**示例 1**（简单流程 7 步 + 4 泳道，对应 `examples/swimlane.drawio` O2O 履约）：

| 节点 | 泳道 | y 坐标 | 对齐原因 |
|---|---|---|---|
| 1. 下单付款 | 用户 | y=60 | 起点 |
| 2. 接单备餐 | 商家 | y=60 | 与 1 跨泳道对齐 |
| 3. 通知派单 | 平台 | y=60 | 与 2 跨泳道对齐 |
| 4. 取餐送达 | 骑手 | y=60 | 与 3 跨泳道对齐 |
| 5. 回传状态 | 骑手 | y=200 | 4→5 同泳道内，y 不同 |
| 6. 推送完成 | 平台 | y=200 | 与 5 跨泳道对齐 |
| 7. 完成评价 | 用户 | y=200 | 与 6 跨泳道对齐 |

**示例 2**（含判断菱形 + 异常分支，对应 `templates/swimlane.drawio` 退款审核，3 层 y=60/240/400）：

| 节点 | 泳道 | y 坐标 | 对齐原因 |
|---|---|---|---|
| 1. 申请退款 | 用户 | y=60 | 起点 |
| 2. 审核（菱形） | 商家 | y=60 | 与 1 跨泳道对齐 |
| 3. 同意退款 | 商家 | y=240 | 同泳道，2 的分支 |
| 4. 拒绝退款 | 商家 | y=400 | 同泳道，2 的分支（错开主流程） |
| 5. 退款处理 | 平台 | y=240 | 与 3 跨泳道对齐 |
| 7. 执行退款 | 支付 | y=240 | 与 5 跨泳道对齐 |
| 6. 更新订单 | 平台 | y=400 | 同泳道 5 的下一步；为避免同泳道同 y 重叠，故意错开 |
| 收到结果 | 用户 | y=400 | 与 4、6 跨泳道对齐 |

## 四、节点形状约定（对应 drawio 样式）

**节点默认尺寸**：所有内容节点（步骤 / 起止 / 判断 / 特殊形状）**width=120, height=60**（容器例外）。

| 节点类型 | ASCII 符号 | drawio style | 几何 (width × height) |
|---|---|---|---|
| 步骤 | `┌──┐ │ │ └──┘` 圆角矩形 | `rounded=1;whiteSpace=wrap;html=1;arcSize=0;` | 120 × 60 |
| 开始 / 结束 | `(  开始  )` 椭圆 | `rounded=1;whiteSpace=wrap;html=1;arcSize=50;` | 120 × 60 |
| 判断 | `◇ 判断 ◇` 菱形 | `rhombus;whiteSpace=wrap;html=1;` | 120 × 60 |
| 跨泳道连接 | `───▶` | `edgeStyle=orthogonalEdgeStyle;rounded=1;orthogonalLoop=1;jettySize=auto;html=1;endArrow=classic;`（**正交折线 + 圆角转角**）| — |

## 五、审查 checklist（subagent 用）

- [ ] 泳道数量符合需求（不限制 2-N）
- [ ] 泳道方向为**纵向**（左右并列），不是上下堆叠
- [ ] 泳道与泳道之间**无缝衔接**（只 1 字符间隔 `│ │`），不留间隙
- [ ] 步骤在泳道内**上下堆叠**（y 递增）
- [ ] 步骤归属唯一泳道
- [ ] 步骤编号连续且单调递增（按主流程时间顺序）
- [ ] 跨泳道箭头都标注了去向（"请求"/"回调"/"通知"）
- [ ] **跨泳道顺序相邻的节点 y 对齐**（让跨泳道边画成水平线）
- [ ] 异常路径（失败、超时）有显式表达
- [ ] 黑白风格（ASCII 草图无颜色填充）
- [ ] drawio 中所有连接采用**正交+圆角**风格（`orthogonalEdgeStyle;rounded=1;...endArrow=classic;`）
- [ ] drawio 中所有内容节点**默认 120x60**（容器除外）
- [ ] 整体宽度 ≤ 80 字符，markdown 代码块完整显示
