## 二、填写说明

| 区域 | 填写要求 |
|---|---|
| 客户端 | 列出所有触达用户的前端形态；如无第三方可不写 |
| 网关层 | 写出核心职责 3-5 个（鉴权、限流、路由、协议转换、灰度） |
| 业务能力层 | 按业务域分组，每域 1-3 个核心服务；命名用"<领域>中心"或"<领域>服务" |
| 基础服务层 | 写出真实使用的存储/中间件；不要写"用不到的组件"凑数 |
| 连线 | 只画**核心依赖**（如"订单中心 → MySQL"），不要画遍所有可能组合 |
| 抽象层级 | 高层版 ≤ 4 个分层；详细版 ≤ 6 个分层；每层 ≤ 6 个一级节点 |
| 宽度 | 整体宽度建议 60-80 字符内，确保代码块在 markdown 中不被截断 |
| drawio 节点尺寸 | **所有内容节点默认 width=120, height=60**（容器 / 分层框可例外） |

## 三、ASCII 符号约定

```
┌──────┐ ┌──────┐  普通矩形（步骤 / 服务 / 模块）
└──────┘ └──────┘

 │      │        上下衔接（无箭头）
 ▼      ▲        带箭头方向

 ──>            标注文字（在线边写"鉴权/限流"等）

(圆柱形用文字表示)  数据库 / 中间件 写"│ MySQL │"或"┌──────┐ │ ╲│ │"等
```

**drawio 边样式（必填）**：所有连接必须用 **正交+圆角** 风格：
```
edgeStyle=orthogonalEdgeStyle;rounded=1;orthogonalLoop=1;jettySize=auto;html=1;endArrow=classic;
```
- `edgeStyle=orthogonalEdgeStyle`：正交折线（不走斜线）
- `rounded=1`：折线转角用圆角而不是直角
- `endArrow=classic`：末端带箭头

**自上而下端点连接（必填）**：所有自上而下的边，起点从源节点**底部**出发，终点连到目标节点**顶部**：
```
exitX=0.5;exitY=1;entryX=0.5;entryY=0;
```
- `exitX=0.5;exitY=1` = 源节点底部中点出
- `entryX=0.5;entryY=0` = 目标节点顶部中点进
- 让架构图"自上而下"流向清晰（上层依赖下层）

## 四、审查 checklist（subagent 用）

- [ ] 分层逻辑清晰：上层依赖下层，不出现"反向依赖"（如基础服务反向调用业务服务）
- [ ] 节点命名一致：同层同类节点用相同后缀（中心/服务/平台）
- [ ] 关键中间件没有遗漏：交易类系统必含 MySQL + Redis + MQ
- [ ] 读者能从左到右 / 从上到下 30 秒看懂主链路
- [ ] 整体宽度 ≤ 80 字符，确保 markdown 代码块完整显示
- [ ] 每个模块都有清晰归属（属于哪一层）
- [ ] drawio 中所有连接采用**正交+圆角**风格（`edgeStyle=orthogonalEdgeStyle;rounded=1;...endArrow=classic;`）
- [ ] drawio 自上而下边的端点为底→顶（`exitX=0.5;exitY=1;entryX=0.5;entryY=0;`）
- [ ] drawio 中所有内容节点**默认 120x60**（容器除外）
- [ ] 分层容器使用**推荐配色**（参见下表）

## 五、产品架构图推荐配色表

4 个分层容器的标准配色（`fillColor` + `strokeColor`），更新模板时保持视觉一致：

| 分层 | fillColor（背景）| strokeColor（边框）|
|---|---|---|
| 用户接入层 | `#dae8fc`（浅蓝）| `#6c8ebf`（深蓝）|
| 网关层 | `#d5e8d4`（浅绿）| `#82b366`（深绿）|
| 业务能力层 | `#fff2cc`（浅黄）| `#d6b656`（深黄）|
| 基础服务层 | `#f8cecc`（浅红）| `#b85450`（深红）|
