# 模板：时序图 ASCII 草图（sequence）

> 适用图类型：**时序图** —— 按时间轴表现对象间消息交互顺序。
> 引用方：SKILL.md 步骤 2。

## 二、填写说明

| 元素 | 填写要求 |
|---|---|
| 参与者 | 2-5 个；按"触发者 → 中间方 → 外部系统"从左到右排列 |
| 生命线 | 参与者按触发顺序排列，第一个 = 流程发起方 |
| 消息 | 实线 `-->` = 同步请求；虚线 `-->>` = 返回/响应；点线 `-.->` = 异步通知 |
| 编号 | 用 `autonumber` 自动编号；消息命名"动词 + 对象" |
| 自调用 | 用 `participant->>participant: 消息` 表示 |
| 分组 | 复杂流程可用 `alt` / `opt` / `loop` / `par` 分块 |
| 列宽 | 每列宽度 12-14 字符，便于阅读 |

## 三、ASCII 排版约定

```
参与者    参与者2   参与者3   参与者4
 │        │        │        │          ← 顶部表头 + 生命线起点
 │ 1.消息 │        │        │
 ├───────▶│        │        │          ← 同步请求
 │        │ 2.返回 │        │          ← 同步响应
 │        │◀───────┤        │
```

## 四、审查 checklist（subagent 用）

- [ ] 参与者按触发顺序从左到右排列，第一个是流程发起方
- [ ] 同步请求用 `->>`，返回/响应用 `-->>`，异步用 `-.->`，箭头方向没反
- [ ] 每条消息有动词性命名（"提交"不是"订单"）
- [ ] 消息编号连续，与 ASCII 草图步骤编号一一对应
- [ ] 关键异常分支用 `alt/else` 或单独消息表达
- [ ] 参与者数量 2-5 个，超出要评估是否需要拆图
- [ ] 没有"无中生有"的返回（请求了 A，对方却返回 B）
- [ ] 整体宽度 ≤ 80 字符，markdown 代码块完整显示
