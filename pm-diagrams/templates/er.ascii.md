# 模板：ER 图 ASCII 草图（er）

> 适用图类型：**ER 图** —— 表现实体、属性、实体间关系。
> 引用方：SKILL.md 步骤 2。

## 一、ASCII 草图模板

```text
┌──────────────┐                ┌──────────────┐
│    用户      │                │    订单      │
│  (User)      │                │  (Order)     │
├──────────────┤                ├──────────────┤
│ PK  id       │                │ PK  id       │
│     username │                │ FK  user_id  │
│     email    │                │     order_no │
│     phone    │                │     amount   │
│     status   │                │     status   │
│     created  │                │     created  │
└──────┬───────┘                └──────┬───────┘
       │                               │
       │ 1                           0..*
       │                               │
       │      ┌──────────────┐          │
       │      │   订单明细    │          │
       └─────▶│ (OrderItem)  │◀─────────┘
              ├──────────────┤
              │ PK  id       │
              │ FK  order_id │
              │ FK  sku_id   │
              │     qty      │
              │     price    │
              └──────┬───────┘
                     │
                     │ 0..*
                     ▼
              ┌──────────────┐
              │    商品      │
              │  (Product)   │
              ├──────────────┤
              │ PK  id       │
              │     name     │
              │     price    │
              │     stock    │
              └──────────────┘
```

## 二、填写说明

| 元素 | 填写要求 |
|---|---|
| 实体 | 命名用单数（User/Order），不缩写为 U/O |
| 主键 | 显式标 PK，命名 `id` 或 `<entity>_id` 二选一并保持一致 |
| 外键 | 显式标 FK，并指向对应实体的主键 |
| 属性 | 主键 + 必要业务字段；非必要字段（如 remark、tag）可省略 |
| 数据类型 | 用 `bigint/string/int/decimal/datetime/bool` 等通用类型 |
| 关系 | 写"动词短语"（"下单"/"包含"/"引用"），不写"关联"这种空话 |
| 基数 | 一侧标基数（1 / 0..* / 1..*），不写"?"这种模糊符号 |
| 宽度 | 实体框宽 12-14 字符，便于阅读 |

## 三、mermaid erDiagram 关系符号（仅作参考，对应 ASCII 用数字写）

```
||--||     一对一        在 ASCII 中写  1 ----- 1
||--o{     一对多（左一右多） ASCII 中写  1 ----- 0..*
||--|{     一对多（强制）   ASCII 中写  1 ----- 1..*
}o--o{     多对多          ASCII 中写  0..* ----- 0..*
```

## 四、审查 checklist（subagent 用）

- [ ] 实体名单数、英文、与代码/表名一致
- [ ] 每个实体有主键 PK，命名统一
- [ ] 外键 FK 都指向真实存在的主键
- [ ] 关系符号方向正确：`||` 在"一"侧，`o{` 在"多"侧
- [ ] 关系动词语义准确（"下单"不是"有关"）
- [ ] 必要属性齐全（金额类标 decimal，时间类标 datetime）
- [ ] 实体数量 3-8 个；超出要评估是否拆图
- [ ] ASCII 中 PK/FK 标记清晰
- [ ] 整体宽度 ≤ 80 字符，markdown 代码块完整显示
